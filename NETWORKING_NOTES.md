### Замена имени сервиса на 127.0.0.1:8001
В таком случае при выполнении запроса в order-service мы будем получать 502 ошибку, тк 127.0.0.1 означает "локальную петлю" которая позволяет обращаться к сервисам, поднятым в рамках текущего контейнера, а контейнер order-service не содержит внутри себя product service, который должен быть на 8001 порту.

### Что произойдет если удалить переменную окружения DISCOUNT_SERVICE_URL
В таком случае order-service будет использовать адрес по умолчанию (127.0.0.1:8003) и получится та же самая проблема, что и в первом пункте

```
Error: Service Unavailable
Response body
{
  "detail": "Discount service is unavailable: All connection attempts failed"
}
```

### Изменение внешнего порта
Повлияет только на то, по какому порту сервис будет доступен на нашем компьютере, но вся сетевая логика взаимодействия между контейнерами останется той же

### Отчет
1. Локальный запуск через 127.0.0.1 возможен благодаря тому, что мы запускаем все сервисы в рамках нашей машины и затем адресуемся по разным портам
2. Ошибка обращения к другому контейнеру через localhost происходит опять же из-за того, что localhost это "локальная петля" позволяющая обратиться к сервисам запущенным в рамках текущей среды (контейнера), но не к другим контейнерам
3. Успешный запуск через docker dns достигается за счёт того, что все 3 конейтнера объединятся в общую сеть, а через docker dns мы можем указать необходимые ip сервисов, которые будут присвоены при старте конейтнеров
4. Мы можем использовать host.docker.internal для того, чтобы получить доступ к приложениям запущенным на нашем хосте. Например можно запустить order-service в контейнере, а discount-service и product-service на своем хосте и затем в docker compose указывать адрес вида host.docker.internal:port
